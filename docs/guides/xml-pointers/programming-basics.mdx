If you already know how to program, most of what you would write in code can be written with [actions](/docs/modules/mechanics/actions-triggers), [filters](/docs/modules/mechanics/filters), and [variables](/docs/modules/mechanics/variables).
This page shows how common code is written in PGM.

| Concept | PGM equivalent |
|---|---|
| Variable | [`<variable>`](/docs/modules/mechanics/variables) |
| Condition | [Filter](/docs/modules/mechanics/filters) |
| Block of code | `<action>` |
| Function | [`<function>`](/docs/modules/mechanics/actions-triggers#functions) |
| Event listener | [`<trigger>`](/docs/modules/mechanics/actions-triggers#trigger-element) |

All values are numbers. Like in C, there is no boolean type.
In the examples below, `condition` is any [filter](/docs/modules/mechanics/filters), `expr` is any [expression](/docs/modules/mechanics/variables#expression-functions), and `...` is more actions.

---

## How It Runs

Actions are usually started by a `<trigger>`, which runs an action when its filter starts allowing.
That action can then run other actions and functions.

Every action runs for one match, team, or player, set by its `scope`.
This works like `this`: in a `player` action, `player_x` is that player's value.

---

## Values

### Variables

Variables are global, like global state in other languages.
They are defined in their own `<variables>` tag, outside of any action, and keep their value for the whole match.
The `scope` can be `match`, `team`, or `player`, to store one value for the match, each team, or each player.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
var x = 0;
var y = 5;
```

</div>
<div>

```xml
<variable id="x" scope="match"/>
<variable id="y" scope="match" default="5"/>
```

</div>
</div>
</div>

Actions can use variables from their own scope or any scope above it.

Arrays hold a fixed number of values, set by a number from 1 to 1024.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
var arr = new Array(10);
```

</div>
<div>

```xml
<array id="arr" scope="match" size="10"/>
```

</div>
</div>
</div>

Local variables are declared with `locals` on an `<action>`, `<repeat>`, or `<function>`, and start at 0 each time it runs.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
let x;
```

</div>
<div>

```xml
<action locals="x">...</action>
```

</div>
</div>
</div>

### Assignment

Variables are changed with the `<set>` action.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
x = expr;
x += expr;
```

</div>
<div>

```xml
<set var="x" value="expr"/>
<set var="x" value="x + expr"/>
```

</div>
</div>
</div>

Arrays also take an `index`.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
arr[i] = expr;
```

</div>
<div>

```xml
<set var="arr" index="i" value="expr"/>
```

</div>
</div>
</div>

Assignments can also be written inline with `:=`, anywhere an action is referenced.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
x = expr;
```

</div>
<div>

```xml
<trigger filter="condition" scope="match" action="x := expr"/>
```

</div>
</div>
</div>

## Control Flow

### Conditions

Conditions are [filters](/docs/modules/mechanics/filters).
A filter defined in `<filters>` is used by its `id`.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (holdingGap) { ... }
```

</div>
<div>

```xml
<action filter="holding-gap">...</action>
```

</div>
</div>
</div>

Filters can also be written [inline](/docs/modules/mechanics/filters#inline-filters), to combine other filters or compare numbers.

#### Combining Conditions

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (a && b) { ... }
if (a || b) { ... }
```

</div>
<div>

```xml
<action filter="all(a, b)">...</action>
<action filter="any(a, b)">...</action>
```

</div>
</div>
</div>

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (!a) { ... }
```

</div>
<div>

```xml
<action filter="not(a)">...</action>
```

</div>
</div>
</div>

#### Comparing Values

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (x == 5) { ... }
if (x != 5) { ... }
```

</div>
<div>

```xml
<action filter="x=5">...</action>
<action filter="not(x=5)">...</action>
```

</div>
</div>
</div>

Greater and less than are written as ranges, with `..` on the open side.
The values in a range must be numbers, not variables or expressions.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (x >= 5) { ... }
if (x <= 5) { ... }
```

</div>
<div>

```xml
<action filter="x=5..">...</action>
<action filter="x=..5">...</action>
```

</div>
</div>
</div>

Inline filters only use inclusive ranges, so `x > 5` is written as `x=6..` for whole numbers.
For decimals, use `not` on the opposite range.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (x > 5) { ... }
if (x < 5) { ... }
```

</div>
<div>

```xml
<action filter="not(x=..5)">...</action>
<action filter="not(x=5..)">...</action>
```

</div>
</div>
</div>

#### Ranges & Expressions

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (x >= 1 && x <= 10) { ... }
```

</div>
<div>

```xml
<action filter="x=1..10">...</action>
```

</div>
</div>
</div>

The left side of a filter can be an expression, as long as it has no parentheses.
Filters with an expression only work in actions, not in triggers.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (x == y) { ... }
if (expr >= 5) { ... }
```

</div>
<div>

```xml
<action filter="x-y=0">...</action>
<action filter="expr=5..">...</action>
```

</div>
</div>
</div>

### If Statements

Actions only run when their `filter` allows, so a `filter` works like an `if` statement.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (condition) { ... }
```

</div>
<div>

```xml
<action filter="condition">...</action>
```

</div>
</div>
</div>

Some single actions can use a `filter` directly.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (condition) return;
if (condition) return expr;
```

</div>
<div>

```xml
<return filter="condition"/>
<return filter="condition" value="expr"/>
```

</div>
</div>
</div>

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (condition) break;
if (condition) continue;
```

</div>
<div>

```xml
<break filter="condition"/>
<continue filter="condition"/>
```

</div>
</div>
</div>

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (condition) f();
```

</div>
<div>

```xml
<call filter="condition" function="f"/>
```

</div>
</div>
</div>

#### If-Else

An `else` is a second action with the opposite filter.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
if (condition) {
    ...
} else {
    ...
}
```

</div>
<div>

```xml
<action filter="condition">...</action>
<action filter="not(condition)">...</action>
```

</div>
</div>
</div>

Each filter is checked when its action runs, so if the first action changes a variable the condition uses, both can run.

### Loops

`<repeat>` runs its actions a number of times.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
for (let i = 0; i < n; i++) { ... }
```

</div>
<div>

```xml
<repeat times="n" index="i">...</repeat>
```

</div>
</div>
</div>

`<switch-scope>` runs its actions once for each team or player.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
for (const player of team.players) { ... }
for (const player of match.players) { ... }
```

</div>
<div>

```xml
<switch-scope outer="team" inner="player">...</switch-scope>
<switch-scope outer="match" inner="player">...</switch-scope>
```

</div>
</div>
</div>

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
for (const team of match.teams) { ... }
```

</div>
<div>

```xml
<switch-scope outer="match" inner="team">...</switch-scope>
```

</div>
</div>
</div>

Loops can be stopped or skipped ahead.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
break;
continue;
```

</div>
<div>

```xml
<break/>
<continue/>
```

</div>
</div>
</div>

`<break/>` only stops the innermost loop.

#### While

There is no `while` loop, but a `<repeat>` with a `<break/>` can be used, up to a maximum number of iterations.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
while (condition) {
    ...
}
```

</div>
<div>

```xml
<repeat times="100">
    <break filter="not(condition)"/>
    ...
</repeat>
```

</div>
</div>
</div>

## Functions & Events

### Functions

Functions are reusable actions with parameters and an optional return value, defined in the `<actions>` tag.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
function f(a, b) { ... }
```

</div>
<div>

```xml
<function id="f" scope="player" params="a,b">...</function>
```

</div>
</div>
</div>

Functions are run with `<call/>`, which can store the returned value.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
f(1, 2);
x = f(1, 2);
```

</div>
<div>

```xml
<call function="f" a="1" b="2"/>
<call function="f" a="1" b="2" result="x"/>
```

</div>
</div>
</div>

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
return expr;
```

</div>
<div>

```xml
<return value="expr"/>
```

</div>
</div>
</div>

A function's `scope` must match the caller's.
Functions can not see the caller's local variables.

### Events

A trigger runs an action when its filter starts allowing, like an event listener.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
when (condition) { ... }
```

</div>
<div>

```xml
<trigger filter="condition" scope="match" action="..."/>
```

</div>
</div>
</div>

Triggers run separately for each player, team, or match, each time their filter changes from deny to allow.

A schedule runs its actions later, up to 1 minute.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
setTimeout(() => { ... }, 5000);
```

</div>
<div>

```xml
<schedule after="5s">...</schedule>
```

</div>
</div>
</div>

Variables are shown in messages using a [`<decimal>`](/docs/modules/mechanics/actions-triggers#decimal-replacement) replacement.

<div className="code-compare">
<div className="code-compare__grid">
<div>

```js
console.log(`${x}`);
```

</div>
<div>

```xml
<message text="{x_text}">
    <replacements>
        <decimal id="x_text" value="x"/>
    </replacements>
</message>
```

</div>
</div>
</div>

## Limitations

- Expressions can't use comparisons or logic like `==` or `&&`. Use a filter instead.
- There are no strings.
- Every loop has a maximum number of iterations.
- A schedule can wait up to 1 minute.
- Another player's variables can only be used by looping over players with `<switch-scope>`.
